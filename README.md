# RSS Watch — Wikipedia Editor Analysis (Static Site)

A plain **HTML / CSS / JavaScript** site (no framework, no build step)
that renders the per-editor reports produced by the
`wiki.py → editor_m.py → report.py` pipeline into:

1. **`index.html`** — a Wikipedia-page overview: aggregate stats, a card
   grid of every editor analyzed, and the highest-scoring hits across
   the whole page.
2. **`editor.html?editor=<slug>`** — a per-editor profile page: account
   info, executive summary, qualitative insight, revision timeline, and
   every flagged hit with its rebuttal, filterable by category.

## How it works

- `scripts/sync_reports.py` reads every `*.json` file from your
  `editor_reports/` folder (the output of `report.py`), **normalizes
  both schema versions**:
  - **old** — `edit_patterns` + `narrative` / `policy_ref` (severity 1–5)
  - **new** — `phobic_references` + `rebuttal` / `rebuttal_source` (score 1–8)

  ...into one consistent shape, and writes static JSON into:
  - `data/index.json`
  - `data/editors/<slug>.json`

- The HTML pages fetch these JSON files at runtime with plain `fetch()`.
  No server-side code is required — this is a fully static site.

- In both schemas, the per-hit "rebuttal" field is shown identically in
  the UI (old `narrative`/`policy_ref` is mapped onto `rebuttal`/
  `rebuttal_source`), so reports generated by either version of
  `report.py` render the same way.

## Usage

### 1. Sync your existing reports (no need to re-run the pipeline)

```bash
# Default source: /home/shri/iBee Analytics/UI/editor_reports
python3 scripts/sync_reports.py

# Or point at a different folder:
EDITOR_REPORTS_DIR="/path/to/editor_reports" python3 scripts/sync_reports.py
```

This is read-only with respect to your reports — it only reads the
existing `*.json` files and writes into `data/`.

### 2. Preview locally

Any static file server works, e.g.:

```bash
python3 -m http.server 8080
# then open http://localhost:8080
```

(Plain `file://` won't work for `fetch()` due to browser CORS rules —
use a local server.)

### 3. Deploy to Vercel

```bash
# from the project root
vercel deploy
```

`vercel.json` is already configured for a static deployment with
`/editor` → `editor.html` and short-cache headers on `/data/*`.

To refresh the site after generating new reports, just re-run
`scripts/sync_reports.py` and re-deploy (or commit the updated
`data/` folder — it's plain JSON and safe to check into git).

## Notes

- Editor slugs are derived the same way as the filenames `editor_m.py`
  already produces (`re.sub(r"[^\w\-]", "_", username)`), so URLs like
  `editor.html?editor=Kautilya3` map directly to
  `data/editors/Kautilya3.json`.
- IP-address editors are detected automatically and shown with a
  distinct "IP Editor" badge/icon.
- If `report.py` hasn't been re-run with the new rebuttal pipeline,
  old reports with `edit_patterns[].narrative` /
  `edit_patterns[].policy_ref` still render correctly — these are
  mapped onto the same "Rebuttal" / "Source" UI as the new
  `phobic_references[].rebuttal` / `.rebuttal_source` fields.
